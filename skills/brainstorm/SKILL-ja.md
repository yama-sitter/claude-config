# Brainstorm — 日本語ミラー

> このファイルは人間用の参照ドキュメントです。Claude は英語版 `SKILL.md` を読みます。

## 目的

実装前の設計思考を協調的な対話で進めるスキル。意図を探り、質問し、設計案を提示してユーザーの承認を得るまで実装に入らない。

`superpowers:brainstorming` の軽量代替。spec ファイルを生成せず、設計内容は会話と agent-memory にのみ残る。

## いつ使うか / 使わないか

**使う場面:**
- 機能作成・コンポーネント構築・機能追加・動作変更など、設計ファーストが有効な全てのタスク

**使わない場面:**
- ユーザーが superpowers ワークフローを明示的に要求したとき（`/superpowers:brainstorming`）
- 明らかな解決策があるシンプルなバグ修正
- コード調査・パターン検索など純粋に調査的なタスク

## 設計意図

- **HARD-GATE**: ユーザーが設計を承認するまで実装コードを書いてはならない。これはどんな「シンプル」なプロジェクトでも例外なく適用される
- **「シンプルすぎて設計不要」アンチパターンへの対処**: 見た目がシンプルなプロジェクトほど未検討の前提が隠れている。短い設計でも提示・承認のプロセスを踏む
- **質問は1つずつ**: 一度に複数の質問を投げない。自然な対話の流れでコンテキストを引き出す
- **コードベース調査を先行**: ユーザーに聞く前にコードベースで答えられることは自分で調査する

## ワークフロー概要

1. コードベースを調査して既存パターンを把握
2. 1つずつ質問して意図・制約・要件を引き出す
3. 設計案（アプローチ・変更ファイル・検証ステップを含む）をまとめて提示
4. ユーザーの承認を得て実装フェーズに引き渡す（agent-memoryに保存）

## brainstorm vs grill-me

| | brainstorm | grill-me |
|---|---|---|
| 目的 | 設計を形成して承認を得る | 既存の設計の穴を発見する |
| 流れ | 対話 → 設計案提示 → 承認 | 徹底的な質問で穴を掘る |
| 用途 | 実装前の設計ファースト | 計画・設計のストレステスト |
