## 目的

定性データ（インタビュー・フィードバック・行動ログ等）から行動パターンとその繋がりを抽出するスキル。「推論のはしご」を1段ずつ登る多フェーズ分析。

## いつ使うか / 使わないか

**使う場面:**
- 生の定性データが手元にあり、複数ケースに跨る共通の行動パターンを発見したいとき

**使わない場面:**
- 仮説が既にあり実験設計をしたいとき
- ブレインストーミングや解決策の評価をしたいとき

## サブコマンド

| 引数 | アクション |
|---|---|
| (なし) | 進捗チェック — レポートの埋まり状態を表示し次のサブコマンドを提案 |
| `brief` | リサーチ起点の定義（フォーカス・ケース・フレーム意識）→ レポートファイル作成 |
| `facts` | 事実の抽出と時系列整理 |
| `phases` | 分析フェーズをユーザーと対話的に定義 |
| `context` | フェーズ別の共通パターン抽出（Narrator → Analyst-Critic → Integration） |
| `synthesis` | パターンの統合（RQコントラスト・パターン間接続・共通ナラティブ） |

## 設計意図

- **段階的分析**: 「事実 → パターン → 統合」の順を守ることで確証バイアスを防ぐ
- **Narrator-Critic パターン**: `context` フェーズでは観察者（Narrator）と批評者（Analyst-Critic）を分離し、各パターンの妥当性を独立に検証する
- **LLMが構造化、人間が解釈**: 分析結果は観察レベルに留める。解釈・意味付けはユーザーが行う
- **レポートファイルによる状態管理**: フェーズ間の状態をファイルで保持するため、セッションをまたいで作業を継続できる

## サブファイルの役割

`references/` 配下の各ワークフローファイル（brief/facts/phases/context/synthesis-workflow.md）は各サブコマンドの具体的な手順を定義する。設計意図やトレードオフを理解するためにはこれらを読む必要がある（→ 日本語ミラー候補）。
