# 引用・主張の規律（日本語ミラー）

> **このファイルは人間用のミラーです。** Claude は英語正本 (`citation-discipline.md`) を読みます。

## いつ適用するか

以下の出力先に事実的な主張を含む場合：(a) ユーザーへのチャット返答、(b) ファイルの Edit/Write、(c) `gh pr *` / `gh issue *` のボディやコメント、(d) コミットメッセージ。

## 三段階の根拠分類

すべての事実的な主張は以下の3段階のいずれかに該当します。主張の表現はその段階に合わせる——低い段階を高い段階として表現しない。

| 段階 | 定義 | 許可される表現 | 禁止される表現 |
|---|---|---|---|
| **Verified（検証済み）** | この会話中のツール呼び出し（Read / Grep / WebFetch / Bash出力）でリテラル文字列が生成され、その主張がその出力の直接引用または自明な言い換えである | `verbatim`、`公式に明記`、`明確に記載`、`as documented at <URL line N>`（引用 + URL + 場所指定付き） | — |
| **Inferred（推論）** | Verified な資料からの推論、または命名・慣例から、または関連はするが同一でないソースから導出 | `I believe`、`appears to`、`based on <X>, likely`、`推測すると`、`〜と思われる` | `verbatim`、`公式に明記`、`間違いなく`、`保証される`、`officially stated` |
| **Recalled（記憶）** | 訓練データまたはこのセッションで再根拠付けされていない過去の会話コンテキストから | `from memory`、`記憶ベースだと`、`if I recall correctly`、`要確認` | すべての Verified 段階の表現；また根拠のある断言表現も避ける |

> **Rationale**: LLM は自信を持って誤った情報を提示しやすい（ハルシネーション）。根拠の段階を明示することで、読み手がどの程度信頼してよいか判断できる。特に PR 本文やコミットメッセージなど、後から参照される成果物では重要。

## NEVER / ALWAYS

- Verified 段階の表現（`公式に明記`、`verbatim`、`明確に記載`、`officially stated`、`as documented`、`間違いなく`、`保証される`）を使うのは、正確な部分文字列を貼り付けられ、かつソースの場所（URL + セクション / ファイル + 行番号）を引用でき、かつそのソースがこの会話で取得されている場合のみ。
  - 悪い例：`公式ドキュメントに「The ignore option is only available for version updates」と明記されている`（言い換えを verbatim として表現）
  - 良い例：`GitHub Dependabot Changelog (2024-XX-XX, https://...) より verbatim: "<実際の正確な部分文字列>"`（この会話でページを再 grep して部分文字列を確認した後のみ）
- 以前の発言から引用文字列を新しい成果物にコピーする際は、ソースに実際に存在するか再検証せずに行わない。以前の発言は Verified でなく Recalled として扱う。
- 外部成果物（PR 本文、コミット、コメント）に公開する前に、引用した部分文字列をこの会話の実際のソース出力に対して再 grep する。正確に一致しない場合は段階を下げる。
- ユーザーが「どこに書いてありますか？」と問い返した場合は、再取得・再読してから verbatim の部分文字列 + 場所指定を報告する。見つからない場合は「見つけられません。以前の主張は Inferred 段階を Verified として表現したものでした。撤回します」と明示する。それが、もっともらしく見えても誤った引用を生み出すより優先される。

## 置換テーブル

左側を書こうとしているときは、根拠の段階に応じて右側の列のいずれかに置き換える。

| 禁止 | 置換（Inferred） | 置換（Recalled） |
|---|---|---|
| `公式に明記されている` | `公式ドキュメントの記述から推測すると` | `記憶ベースだが、公式ドキュメントにそのような記述があったはず（要確認）` |
| `verbatim quote: "..."` | `paraphrase: ...` | `from memory, roughly: ...` |
| `間違いなく / 保証される` | `おそらく / 〜と考えられる` | `記憶ベースで断言できないが` |
| `as documented at <URL>` | `inferred from <URL>` | `believed to be in <URL>, not re-checked` |

## 圧力への対応

レビュアー・ユーザーが以前の主張の根拠を求めた場合：

- 「正しそうな」新しい引用を生成しない。具体性への圧力がかかるこの瞬間こそ、捏造が生まれやすい。
- まず再取得・再 grep する。その後、(a) verbatim の部分文字列 + 場所指定が見つかれば報告、または (b) 明示的に撤回：「見つけられません。Inferred / Recalled に格下げします」。
- 撤回はもっともらしい引用より優先される。ユーザーはすでに信頼度の較正を失っている。もう一つの捏造は、認めることより悪い。
