# コンテキスト圧力ガイドライン（日本語ミラー）

> **このファイルは人間用のミラーです。** Claude は英語正本 (`context-pressure.md`) を読みます。

## いつ適用するか

長い会話や複雑なタスク中に、継続的な自己チェックとして適用します。

## 自己診断チェックリスト

以下のいずれかを行っていないか確認してください：

- この会話で関連するソースファイルを読まずにコードを書いている
- ファイルの内容を再読せずに記憶から埋めている
- 速度を出すために検証・テストのステップを省いている
- 具体性が必要な場面で曖昧・一般的な応答をしている
- 会話の前半で行われた決定を忘れている
- すでに完了した作業を繰り返している

いずれかに該当する場合は、コンテキスト圧力がかかっています。

> **Rationale**: コンテキスト圧力下では「分かったふりをして続行」するよりも「圧力を宣言して対処」する方が最終的な品質が高くなる。誤りを早期に認識・宣言することが重要。

## コンテキスト圧力下での必須動作

- ユーザーに対して明示的にコンテキスト圧力を宣言してから続行する
- 関連するソースファイルを読まずにコードを書かない
- 検証・テストのステップを省かない
- タスクが Plan Mode を必要とする場合は省略しない
- 作業をオフロードしてコンテキストを保全するためにサブエージェントを活用する
- タスクを適切に完了できない場合は、低品質な出力を生成するより停止する

## 推奨する対処法

### サブエージェント委譲

以下の場合にサブエージェントに委譲する：

- 3ファイル以上の探索的調査 → Explore サブエージェント（数ファイルの読み取りには不使用）
- テスト実行・検証 → サブエージェントがテストを実行し、サマリーのみ返す
- コードレビュー → code-reviewer サブエージェント
- 大量のログ・テスト出力の分析 → サブエージェントが処理してサマリーを返す

サブエージェントは親のコンテキストを消費しない。調査の詳細はサブエージェント内に留まり、サマリーのみが戻る。

### コンテキスト回復

- 次のフェーズに移る前に完了した作業をまとめる
- 先のコンテキストに頼らず、重要なファイルを再読する
- 残りの作業を新しい会話に分割することを提案する

## 出力制御（コンテキスト節約）

- ファイルの内容を会話に丸ごと返さない
- ファイルの必要な範囲だけを読む（offset/limit パラメータを使用）。ファイル全体を読まない
- 広範な探索には、Glob/Grep を繰り返すのではなく Explore サブエージェントを使用する
